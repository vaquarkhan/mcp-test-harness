Testing mode

Security testing

MCP Test Harness owns the CI gate: deterministic security payloads, auth boundaries, quality gate, and manifest rug-pull. Runtime enforcement stays with MCP-Bastion.

CI gate
quality_gate + SARIF
Suite A
egress · covert · exec
Supply chain
manifest rug-pull
injection traversal secret leak Suite A egress manifest_gate
Full rationale: Why security-first in the handbook.

What to enable

quality_gate:
  require_security_tests: true
  fail_on_severity: high
manifest_gate:
  enabled: true
  path: __snapshots__/mcp_manifest.snap

Payload helpers

  • assert_injection_blocked / assert_path_traversal_blocked / assert_no_secret_leak
  • assert_egress_quarantined / assert_egress_allowed — Suite A semantic egress (recorded-verdict CI)
  • assert_covert_channel_neutralized — known encodings only
  • assert_general_exec_tools_absent — capability-reduction config check
from mcp_test_harness import marker, assert_egress_quarantined, assert_egress_allowed

@marker(tags=["security", "semantic-egress"])
async def test_egress(mcp_server):
    await assert_egress_quarantined(mcp_server, "send_message")
    await assert_egress_allowed(mcp_server, "send_message")

Commands

mcp-test -m security
mcp-test --sarif-output findings.sarif
mcp-test manifest check
mcp-test --report-format html --report-output report.html

Markers semantic_live and adaptive are reserved for nightly detection-quality runs — they must not gate PRs.

Lifecycle

Scan / config → Test / CI (this harness) → Enforce / runtime (Bastion)
